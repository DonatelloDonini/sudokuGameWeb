# sudokuGameWeb
 The classic Sudoku game, made in JavaScript: solo games with a leaderboard and online battles between players with the same elo.

## Features
- **Playable on any screen**: click or tap a cell and use the number pad, or play with the keyboard. The layout adapts from phones to large monitors.
- **Difficulty graded by the reasoning a puzzle needs**, not by how many cells are empty (see [Difficulty](#difficulty)). Every puzzle has a single solution and can be solved with logic alone.
- **Pencil mode** to write notes in the cells. Placing a number clears it from the notes of its row, column and box.
- **Mistakes in red**, undo, erase, and a counter of how many of each number are still missing.
- **Hints** (each adds 30 seconds to your time) and a **solution** button (ends the game, which won't be ranked).
- **Accounts and leaderboards**: best time of each player for every difficulty, and the battle elo ranking.
- **Online battles**: players are matched with someone with their exact elo (the accepted gap widens by 25 points every 5 seconds of waiting), both get the same puzzle at the same time, and the first to solve it wins the elo points. You see your opponent's progress, not their numbers. A dropped connection or a page reload has 20 seconds to come back before the battle is lost.
- **A new color palette every visit**, generated like in the [minesweeper game](https://github.com/DonatelloDonini/minesweeper-javascript): five harmonious colors mapped to the page theme, reversed when the browser is in dark mode.
- **In-game rules**: the `?` button in the top right corner explains how to play.
- **A public API for developers** (see [Public API](#public-api-for-developers)): graded puzzles, a solver, a difficulty grader and step by step hints for other sudoku games, documented at `/api.html`.

The solution of a game never leaves the server until the player asks for it, and times are measured by the server, so the leaderboard can't be cheated from the browser.

## Difficulty

`HumanSolver` solves a puzzle the way a person would: with logical techniques only, always using the easiest one that makes progress. The techniques are grouped in tiers, one per difficulty:

| Difficulty | Techniques of its tier |
|------------|------------------------|
| Easy       | hidden single, naked single |
| Medium     | pointing, box/line reduction, naked pair, hidden pair |
| Hard       | naked triple, hidden triple, X-Wing |
| Expert     | XY-Wing, XYZ-Wing, Swordfish |

To build a level, a random solved grid (from `SudokuGrid.generateLevel`) is emptied cell by cell in random order. A cell is only emptied if the puzzle can still be solved with the techniques up to the difficulty's tier (`SudokuGrid.unsolveLogically`), so the puzzle never needs harder reasoning and always has a single solution. The level is then kept only if it really needs a technique of its tier: an "expert" puzzle that turns out to need only pairs is thrown away. Easy levels also stop at 45 empty cells, so they are quick as well as simple.

Hard puzzles are rare (about 1 attempt in 40 needs a triple or an X-Wing), so `LevelPool` keeps 5 levels of every difficulty ready, generated by a worker thread: players never wait and the server never freezes. The hardest technique and the score of each level are stored with the game and shown to the player after solving it.

## Running with Docker

```sh
docker compose up --build
```

Then open http://localhost:3000. Set `PORT` to use a different host port, e.g. `PORT=8080 docker compose up --build`.

The database is stored in the `sudoku-data` volume, so accounts and rankings survive restarts and rebuilds (`docker compose down -v` deletes them).

When the game is served over HTTPS (e.g. behind a reverse proxy), set `COOKIE_SECURE=true` so the session cookie is only sent over HTTPS. The proxy must forward websocket upgrades on `/ws`.

## Running locally

Requires Node.js 22.13 or newer (the database uses the built-in `node:sqlite` module).

```sh
cd backend
npm install
npm start        # or `npm run dev` to restart on file changes
npm test
```

The frontend must be opened through the backend (http://localhost:3000), not as a file or through a separate static server, because it talks to the API.

## Public API for developers

Other sudoku games can use this server instead of writing their own generator. The full documentation, with examples and a "try it" form, is served at `/api.html`.

| Method | Path | Description |
|--------|------|-------------|
| `GET`  | `/api/v1/puzzles?difficulty=hard&count=3&format=string` | New graded puzzles with their solution, hardest technique and score (up to 10) |
| `POST` | `/api/v1/solve` | `{puzzle}`: the solution and whether it is unique |
| `POST` | `/api/v1/grade` | `{puzzle}`: the difficulty of any puzzle and the techniques it needs |
| `POST` | `/api/v1/hint` | `{puzzle}`: the next number a person could place, the technique, and the deductions leading to it |
| `GET`  | `/api/v1/difficulties` | The difficulties and their techniques |

- Puzzles are 9x9 arrays (`null` or `0` for empty cells) or 81 character strings (`.` or `0` for empty cells); `?format=array|string` chooses the output format.
- No account or key: CORS is open to any origin and no cookies are used.
- Rate limited per IP (`PUBLIC_API_RATE_LIMIT`, 60 per minute by default; every generated puzzle counts as one request), with `RateLimit-*` headers and `429` + `Retry-After` over the limit. Behind a reverse proxy, set `TRUST_PROXY` so the limit applies to the real client IP.
- API puzzles are generated by the worker thread, after the ones the game is waiting for, without using the levels kept ready for the players. When more than 50 are waiting, the API answers `503` with `Retry-After`.

## Game API

These endpoints are used by the game itself. All bodies are JSON. The session is kept in an httpOnly cookie. Boards are 9x9 arrays indexed as `board[y][x]`, with `null` for empty cells.

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/api/auth/register` | `{username, password}`: creates an account and logs in |
| `POST` | `/api/auth/login` | `{username, password}` |
| `POST` | `/api/auth/logout` | |
| `GET`  | `/api/auth/me` | The logged in user with their stats, or `null` |
| `POST` | `/api/games` | `{difficulty}`: starts a game, returns `{id, puzzle, ranked, ...}` (ranked when logged in) |
| `POST` | `/api/games/:id/hint` | `{board}`: returns `{x, y, value}`, fixing a mistake first if there is one |
| `POST` | `/api/games/:id/solution` | Ends the game and returns the solution |
| `POST` | `/api/games/:id/complete` | `{board}`: `{solved: false}`, or `{solved: true, durationMs, rank, ...}` |
| `GET`  | `/api/leaderboard/elo` | Battle ranking |
| `GET`  | `/api/leaderboard/times/:difficulty` | Best time of each player |
| `GET`  | `/api/health` | `{"status": "ok"}`, used by the Docker health check |

### Battle websocket (`/ws`, logged in users only)

Client messages: `{type: "join-queue"}`, `{type: "leave-queue"}`, `{type: "move", x, y, value}`, `{type: "resign"}`.

Server messages: `welcome`, `queue-joined`, `queue-left`, `battle-start` (puzzle, opponent, countdown), `opponent-progress`, `opponent-connection`, `board-incorrect`, `battle-end` (result, elo change, solution), `replaced` (the account connected from another window), `error`.

## Configuration

| Variable        | Default                  | Description                                   |
|-----------------|--------------------------|-----------------------------------------------|
| `PORT`          | `3000`                   | Port the server listens on                    |
| `HOST`          | `0.0.0.0`                | Interface the server binds to                 |
| `DATABASE_PATH` | `backend/data/sudoku.db` | SQLite database file (`/app/data/sudoku.db` in Docker) |
| `COOKIE_SECURE` | `false`                  | Mark the session cookie as HTTPS only         |
| `PUBLIC_API_RATE_LIMIT` | `60`             | Public API requests (or generated puzzles) per minute and IP |
| `TRUST_PROXY`   | `false`                  | Express "trust proxy": `true`, a number of proxies, or their IPs |
| `FRONTEND_DIR`  | `frontend/`              | Folder with the static frontend files         |
| `DEBUG_SUDOKU_GENERATOR` | `false`         | Log the generator's row restarts              |

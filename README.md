# sudokuGameWeb
 The classic Sudoku game, made in JavaScript: solo games with a leaderboard and online battles between players with the same elo.

## Features
- **Playable on any screen**: click or tap a cell and use the number pad, or play with the keyboard. The layout adapts from phones to large monitors.
- **Difficulty graded by the reasoning a puzzle needs**, not by how many cells are empty (see [Difficulty](#difficulty)). Every puzzle has a single solution and can be solved with logic alone.
- **Pencil mode** to write notes in the cells. Placing a number clears it from the notes of its row, column and box.
- **Mistakes in red**, undo, erase, and a counter of how many of each number are still missing.
- **Hints** (each adds 30 seconds to your time) and a **solution** button (ends the game, which won't be ranked).
- **Accounts and leaderboards**: best time of each player for every difficulty, and the battle elo ranking.
- **Online battles**: players are matched with someone with their exact elo (the accepted gap widens by 25 points every 5 seconds of waiting), both get the same puzzle at the same time, and the first to solve it wins the elo points. You see your opponent's progress, not their numbers. A dropped connection or a page reload has 20 seconds to come back before the battle is lost.
- **A new color palette every visit**, generated like in the [minesweeper game](https://github.com/DonatelloDonini/minesweeper-javascript): five harmonious colors mapped to the page theme, reversed when the browser is in dark mode.
- **In-game rules**: the `?` button in the top right corner explains how to play.
- **A landing page** (`/`) presenting the game, the game itself at `/play/`, and a **developers area** (`/developers/`) documenting the public API, kept out of the game.
- **A public API for developers** (see [Public API](#public-api-for-developers)): graded puzzles, a solver, a difficulty grader and step by step hints for other sudoku games.
- **Plays offline** (see [Offline](#offline)): the game is kept on the device by a service worker, with 5 puzzles of every difficulty to play without a connection. It can be installed as an app.
- **Pixel avatars**: players build their own pixel-art face with the [pixel-avatar](#the-pixel-avatar-module) module; it shows in the header, the leaderboards, the battles and the admin dashboard.
- **Cheating reports**: players can report an opponent from the end of a battle, or any player from the leaderboard.
- **Admin dashboard** (see [Admin dashboard](#admin-dashboard)), built like the OpenCV Editor's: stats, reports with the evidence, users (ban, admin rights), battles, solo games and the state of the server.
- **Tested end to end** (see [Tests](#tests)): backend, frontend logic and the whole game in a real browser, on desktop and phone, on every push.

## Difficulty

`HumanSolver` solves a puzzle the way a person would: with logical techniques only, always using the easiest one that makes progress. The techniques are grouped in tiers, one per difficulty:

| Difficulty | Techniques of its tier |
|------------|------------------------|
| Easy       | hidden single, naked single |
| Medium     | pointing, box/line reduction, naked pair, hidden pair |
| Hard       | naked triple, hidden triple, X-Wing |
| Expert     | XY-Wing, XYZ-Wing, Swordfish |

To build a level, a random solved grid (from `SudokuGrid.generateLevel`) is emptied cell by cell in random order. A cell is only emptied if the puzzle can still be solved with the techniques up to the difficulty's tier (`SudokuGrid.unsolveLogically`), so the puzzle never needs harder reasoning and always has a single solution. The level is then kept only if it really needs a technique of its tier: an "expert" puzzle that turns out to need only pairs is thrown away. Easy levels also stop at 45 empty cells, so they are quick as well as simple.

Hard puzzles are rare (about 1 attempt in 40 needs a triple or an X-Wing), so `LevelPool` keeps 5 levels of every difficulty ready, generated by a worker thread: players never wait and the server never freezes. The hardest technique and the score of each level are stored with the game and shown to the player after solving it.

## The pixel-avatar module

The avatars come from [pixel-avatar](https://github.com/DonatelloDonini/pixel-avatar), a separate npm package in a private GitHub repository. The server depends on it (`backend/package.json`, pinned to the module's exact commit), uses it to check and draw the avatars, and serves its browser files at `/vendor/pixel-avatar/`. The pages import it as `"pixel-avatar"` through an import map, like in Node.js.

Installing the dependencies therefore needs read access to that repository:

- **On your machine**: your usual GitHub access (an SSH key, or a credential helper for HTTPS).
- **Docker**: a read-only GitHub token in `GITHUB_TOKEN`, passed to the build as a secret (it is never stored in the image).
- **GitHub Actions**: a repository secret named `PIXEL_AVATAR_TOKEN` with the same token.

A fine-grained personal access token with read-only access to the *contents* of `pixel-avatar` is enough. To update the module, push the new version there, then put its commit in `backend/package.json` (or a tag, once there are some: `github:DonatelloDonini/pixel-avatar#v1.1.0`) and run `npm install` in `backend/`.

## Running with Docker

```sh
GITHUB_TOKEN=<read-only token for pixel-avatar> docker compose up --build
```

Then open http://localhost:3000. Set `PORT` to use a different host port, e.g. `PORT=8080 docker compose up --build`.

The database is stored in the `sudoku-data` volume, so accounts and rankings survive restarts and rebuilds (`docker compose down -v` deletes them).

When the game is served over HTTPS (e.g. behind a reverse proxy), set `COOKIE_SECURE=true` so the session cookie is only sent over HTTPS. The proxy must forward websocket upgrades on `/ws`.

## Running locally

Requires Node.js 22.13 or newer (the database uses the built-in `node:sqlite` module).

```sh
cd backend
npm install
npm start        # or `npm run dev` to restart on file changes
npm test
```

The frontend must be opened through the backend (http://localhost:3000), not as a file or through a separate static server, because it talks to the API.

## Offline

Once the game has been opened online, it works without a connection:

- `frontend/sw.js` (a service worker) keeps the game's pages, styles and modules on the device. It always tries the network first, so updates arrive as soon as the device is online, and never caches the API (except the avatar images, which never change).
- `OfflineLevels` keeps 5 puzzles of every difficulty in the browser's storage, downloaded from the public API with their solution, and refills them whenever the game is online.
- Offline, "New game" plays a saved puzzle (another difficulty if none of the chosen one is left): hints, the solution and the check happen on the device. These games aren't ranked, and battles need a connection.
- An online game finished while offline is sent to the server when the connection is back, so its time still counts.

`tests/frontend/serviceWorker.test.js` follows every import of the game and fails when a file is missing from the service worker's list.

## Admin dashboard

`/admin.html` is for admins only. Make the first admin from the command line once their account exists (afterwards, admins can make other admins from the Users page):

```sh
# with Docker
docker compose exec sudoku node backend/src/cli.js make-admin <username>
# locally
cd backend && npm run admin -- make-admin <username>
```

The same tool has `remove-admin` and `unban`. The dashboard has, in its side menu (collapsible, remembered by the browser, with `admin.html#<page>` links):

- **Stats**: players, activity today, games, battles and open reports; games, battles and new players per day (week, month, year, all time); solo games per difficulty.
- **Reports**: the cheating reports. A report shows the reported player's history (elo, battles, best solo times next to everybody's average, previous reports) and, for a battle, how both players played it from the recorded moves: correct cells, mistakes, corrections, typical time per number, fastest 10 numbers, a chart of the correct cells over time, and warning signs (no mistake at all, less than 1.5 s per number, 10 numbers in less than 6 s, very regular rhythm). The admin dismisses the report or bans the player.
- **Users**: search, ban (with a reason shown to the player) and unban, give or remove admin rights.
- **Battles** and **Solo games**: the last 200 of each.
- **System**: uptime, memory, database size, players connected, queued and battling, levels ready in the generator, refreshed every 5 seconds.

A banned player is logged out everywhere, loses any battle they're in, can't log in, and leaves the leaderboards.

## Tests

```sh
npm install --prefix backend && npm install   # once
npx playwright install chromium               # once, the browser of the browser tests

npm test                # everything
npm run test:backend    # the server: sudoku logic, solver, generator, API, battles, websocket, reports, admin, avatars
npm run test:frontend   # the frontend logic: game state, notes, undo, API client, battle connection, offline puzzles, service worker list
npm run test:e2e        # the whole game in Chromium, desktop and phone (Pixel 7)
```

The browser tests start the real server on a throwaway database (`.e2e-data/`) and play like a person: the landing page and the developers area, solo games with conflicts, undo, notes, hints and the solution, accounts and leaderboards, avatars, two-player battles with a reload in the middle, reports, the admin dashboard banning a cheater, and playing offline. When one fails, `npm run test:e2e:report` (or the `playwright-report` artifact on GitHub) shows a screenshot and a trace of every step.

GitHub Actions runs all the tests and builds and starts the Docker image on every push and pull request (`.github/workflows/tests.yml`).

## Public API for developers

Other sudoku games can use this server instead of writing their own generator. The full documentation, with a quick start, examples and a "try it" form, is the developers area at `/developers/` (the old `/api.html` address redirects there).

| Method | Path | Description |
|--------|------|-------------|
| `GET`  | `/api/v1/puzzles?difficulty=hard&count=3&format=string` | New graded puzzles with their solution, hardest technique and score (up to 10) |
| `POST` | `/api/v1/solve` | `{puzzle}`: the solution and whether it is unique |
| `POST` | `/api/v1/grade` | `{puzzle}`: the difficulty of any puzzle and the techniques it needs |
| `POST` | `/api/v1/hint` | `{puzzle}`: the next number a person could place, the technique, and the deductions leading to it |
| `GET`  | `/api/v1/difficulties` | The difficulties and their techniques |

- Puzzles are 9x9 arrays (`null` or `0` for empty cells) or 81 character strings (`.` or `0` for empty cells); `?format=array|string` chooses the output format.
- No account or key: CORS is open to any origin and no cookies are used.
- Rate limited per IP (`PUBLIC_API_RATE_LIMIT`, 60 per minute by default; every generated puzzle counts as one request), with `RateLimit-*` headers and `429` + `Retry-After` over the limit. Behind a reverse proxy, set `TRUST_PROXY` so the limit applies to the real client IP.
- API puzzles are generated by the worker thread, after the ones the game is waiting for, without using the levels kept ready for the players. When more than 50 are waiting, the API answers `503` with `Retry-After`.

## Game API

These endpoints are used by the game itself. All bodies are JSON. The session is kept in an httpOnly cookie. Boards are 9x9 arrays indexed as `board[y][x]`, with `null` for empty cells.

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/api/auth/register` | `{username, password}`: creates an account and logs in |
| `POST` | `/api/auth/login` | `{username, password}` |
| `POST` | `/api/auth/logout` | |
| `GET`  | `/api/auth/me` | The logged in user with their stats, or `null` |
| `POST` | `/api/games` | `{difficulty}`: starts a game, returns `{id, puzzle, ranked, ...}` (ranked when logged in) |
| `POST` | `/api/games/:id/hint` | `{board}`: returns `{x, y, value}`, fixing a mistake first if there is one |
| `POST` | `/api/games/:id/solution` | Ends the game and returns the solution |
| `POST` | `/api/games/:id/complete` | `{board}`: `{solved: false}`, or `{solved: true, durationMs, rank, ...}` |
| `GET`  | `/api/leaderboard/elo` | Battle ranking |
| `GET`  | `/api/leaderboard/times/:difficulty` | Best time of each player |
| `POST` | `/api/auth/avatar` | `{avatar}`: an avatar code (pixel-avatar), saved as the player's avatar |
| `GET`  | `/api/avatars/:code.svg` | Any avatar as an SVG image (`?size=24-512`), cached forever |
| `GET`  | `/api/reports/reasons` | The reasons a player can be reported for |
| `POST` | `/api/reports` | `{username, battleId?, reason, comment?}`: reports a player (logged in; 10 a day at most) |
| `GET`/`POST` | `/api/admin/...` | The admin dashboard: `stats`, `system`, `battles`, `games`, `users` (+ `ban`, `unban`, `admin`), `reports` (+ `resolve`); admins only |
| `GET`  | `/api/health` | `{"status": "ok"}`, used by the Docker health check |

### Battle websocket (`/ws`, logged in users only)

Client messages: `{type: "join-queue"}`, `{type: "leave-queue"}`, `{type: "move", x, y, value}`, `{type: "resign"}`.

Server messages: `welcome`, `queue-joined`, `queue-left`, `battle-start` (puzzle, opponent, countdown), `opponent-progress`, `opponent-connection`, `board-incorrect`, `battle-end` (result, elo change, solution), `replaced` (the account connected from another window), `error`.

## Configuration

| Variable        | Default                  | Description                                   |
|-----------------|--------------------------|-----------------------------------------------|
| `PORT`          | `3000`                   | Port the server listens on                    |
| `HOST`          | `0.0.0.0`                | Interface the server binds to                 |
| `DATABASE_PATH` | `backend/data/sudoku.db` | SQLite database file (`/app/data/sudoku.db` in Docker) |
| `COOKIE_SECURE` | `false`                  | Mark the session cookie as HTTPS only         |
| `PUBLIC_API_RATE_LIMIT` | `60`             | Public API requests (or generated puzzles) per minute and IP |
| `TRUST_PROXY`   | `false`                  | Express "trust proxy": `true`, a number of proxies, or their IPs |
| `FRONTEND_DIR`  | `frontend/`              | Folder with the static frontend files         |
| `DEBUG_SUDOKU_GENERATOR` | `false`         | Log the generator's row restarts              |
